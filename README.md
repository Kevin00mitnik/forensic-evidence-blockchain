# Forensic Evidence Ledger

An educational forensic-evidence application with two modes:

- **Local mode (default):** Flask stores uploaded evidence locally and appends SHA-256 custody records to a local JSON hash chain.
- **Ethereum mode:** Flask and Web3.py store the evidence SHA-256, sanitized filename, registering address, and custody-event history in an `EvidenceCustody` Solidity contract deployed to a local Ganache chain. The uploaded file itself stays on the computer running Flask.

The Ethereum workflow demonstrates registering evidence, comparing a file to an on-chain hash, and recording and viewing custody events. MySQL is not required: the small demo keeps its optional local-mode ledger in JSON and its Ethereum-mode evidence metadata in the contract.

> **For learning only.** Do not upload real forensic evidence or confidential files. Local Ganache is not a public or production network. The demo uses an unlocked development test account and has no user authentication, authorization, trusted clock, privacy, legal identity proof, or production-grade chain-of-custody controls. Ethereum filenames, hashes, addresses, and custody labels are visible to anyone with access to the chain. Blockchain timestamps are approximate. A file hash proves only that bytes match a recorded digest; it does not prove who created the file or that the chain of custody is truthful.

## Requirements

- Python 3.10 or newer
- Node.js LTS and npm (only for Ethereum mode; Ganache is downloaded by `npx`)
- PowerShell on Windows (the commands below use PowerShell syntax)

## Install

From the repository directory:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If PowerShell blocks virtual-environment activation, allow it for the current terminal only, then activate:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

For a local-only demo, start the app now:

```powershell
python app.py
```

Open <http://127.0.0.1:5000>. Local mode stores files under `data/uploads/` and metadata in `data/ledger.json`. Set `EVIDENCE_DATA_DIR` to use another local directory. The default local ledger is useful for learning about hashes, but it is not a blockchain.

## Run the Ganache/Ethereum workflow

Open **two PowerShell windows** in the repository directory. In the first, start Ganache with deterministic, disposable local test accounts:

```powershell
.\scripts\start_ganache.ps1
```

Leave this window running. The script serves JSON-RPC at `http://127.0.0.1:7545` on Ganache's local development chain ID `1337`; its deterministic account keys are generated by Ganache for local development and are not stored in this repository. Never use Ganache test accounts or keys with real funds.

In the second window, activate the virtual environment if needed and deploy the contract:

```powershell
.\.venv\Scripts\Activate.ps1
python .\scripts\deploy_contract.py
```

The first deployment may download Solidity compiler 0.8.24 through `py-solc-x`. The script compiles `contract/EvidenceCustody.sol`, deploys from the first unlocked Ganache account, and saves the public ABI/address to `contract/deployment.json`. That generated deployment file is ignored by Git.

Select Ethereum mode and run Flask in that same second window:

```powershell
$env:EVIDENCE_BACKEND = "ethereum"
python app.py
```

Then open <http://127.0.0.1:5000>. Upload a file to register it; choose a file and record to verify; use the custody-event form to add `RECEIVED`, `ACCESSED`, `SEALED`, or `TRANSFERRED` history entries. Each transaction is submitted by Ganache's first unlocked account. Restarting Ganache with its default in-memory chain clears contract data, so deploy the contract again after a restart. Run `python app.py` in a fresh shell without setting `EVIDENCE_BACKEND` to return to local mode.

### Ethereum configuration

The defaults match the included local Ganache script. Optional variables:

| Variable | Default | Purpose |
|---|---|---|
| `EVIDENCE_BACKEND` | `local` | Select `local` or `ethereum`. |
| `EVIDENCE_RPC_URL` | `http://127.0.0.1:7545` | Local JSON-RPC endpoint used by deployment and the app. |
| `EVIDENCE_DEPLOYMENT_FILE` | `contract/deployment.json` | Path to the generated ABI/address file. |
| `EVIDENCE_CONTRACT_ADDRESS` | Address from deployment file | Override the deployed contract address. |
| `EVIDENCE_ACCOUNT` | First unlocked node account | Select another unlocked local development account. |
| `EVIDENCE_DATA_DIR` | `data/` | Local evidence-file storage and local-mode ledger directory. |

The app deliberately accepts only an unlocked account exposed by the connected node; it does not load or persist private keys. Keep the RPC endpoint bound to localhost. Do not expose Ganache or use this example with a public RPC endpoint or mainnet account.

## What is stored where

In both modes, the app saves uploaded file bytes locally under `EVIDENCE_DATA_DIR/uploads/`, named by their SHA-256 digest. Uploads are limited to 16 MiB and empty files are rejected. In local mode, custody records are in `ledger.json`. In Ethereum mode, the contract stores the file hash, sanitized filename, registering address, block timestamp, and each custody event's action/address/timestamp; the chain does **not** store the file bytes. There is no MySQL database in this implementation.

The Ethereum **Verify** action hashes the supplied file and compares it with the selected contract record. The Ethereum records check reads all evidence and custody entries from the connected contract and checks their sequential IDs and hash shape; it is not an audit of the node, validator set, deployment source, or real-world custody claims. The local-mode ledger check instead recomputes the JSON hash chain.

## Tests

The automated tests use the existing local mode and an injected fake Web3 contract, so they do not need Ganache to be running:

```powershell
python -m unittest discover -s tests -v
```

For a manual real-chain check, follow the Ganache workflow above, register a disposable test file, compare it, and add a custody event. Never commit uploaded files, `data/`, deployment details, private keys, certificates, or personal information.
